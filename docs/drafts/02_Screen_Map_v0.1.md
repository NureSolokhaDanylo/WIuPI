## 4. Текстові User Flows для ключових сценаріїв MVP

1. **Створення заявки співробітником та перевірка початкових значень (`US-01`):**
   `S-02-A (Tickets List)` → клік `+ Create Ticket` → `M-01 (Create Ticket Modal)`: спроба натиснути `Create` без теми → помилка `"Subject is required"` (`T-06`) → заповнення `Subject`, вибір `Category = Hardware`, заповнення `Description` → клік `Create` (`T-07`) → перехід на `S-03` нової заявки (`Status = Open`, `Priority = Not Set`, `Assignee = Unassigned`, `Author = Олена Коваль`, управлінські поля в режимі read-only).
2. **Тріаж заявки IT-спеціалістом: зміна категорії, призначення виконавця та встановлення пріоритету (`US-03`, `US-04`, `BR-02.1`):**
   `S-02-A (All Tickets, IT Specialist Ігор Мельник)` → клік на нову заявку `TCK-006` (`T-08`) → `S-03`: зміна `Category` за потреби + `Apply`, вибір `Assignee = Ігор Мельник` + `Apply`, вибір `Priority = High` + `Apply` (`T-10`) → заявка отримує виконавця й високий пріоритет і стає видимою у вкладці `S-02-B (Important Tickets)`.
3. **Виконання заявки призначеним IT-спеціалістом (`US-07`, `BR-08.1`):**
   `S-03 (IT Specialist Ігор Мельник — Current Assignee)` → вибір `In Progress` + `Apply` (`T-11a`) → після вирішення проблеми вибір `Resolved` + `Apply` → у стані `Resolved` заявка все ще відображається в `S-02-B (Important Tickets)` (`BR-09.1`), а виконавець може або повернути її в роботу `Resolved → In Progress` (`T-11b`), або остаточно закрити `Resolved → Closed` (`T-11a`) → після вибору `Closed` + `Apply` контрол `Status` блокується (`No further transitions`), заявка виключається з `S-02-B`.
4. **Блокування зміни статусу для непризначеного IT-спеціаліста (`AC-07.4`, `BR-08`):**
